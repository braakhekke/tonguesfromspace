# CLAUDE.md: Swiss Glacier Tongues from Space

Public dashboard of the tongues of the ten largest Swiss glaciers in Sentinel-2 imagery, one clear late-summer scene per year since 2016, with GLAMOS statistics, a single-image export and an animation (video) export. Site: https://braakhekke.github.io/tonguesfromspace/. Non-commercial (see Licences).

## Data flow

```
browser ── /cdse/statistics, /cdse/process ──> relay ──> Copernicus Data Space (Sentinel Hub APIs)
           relay = worker/worker.js on the public site (config.js), scripts/serve.py locally
```

- **Scene choice:** Statistical API, Sentinel-2 L2A, SCL classes (cloud 3, 8, 9, 10; snow 11), 1 July to 20 September (`LAST_DAY`; 2024 until 14 September). Each day is scored per orbit (a day can hold two passes, e.g. R108 and R065), so a scene is date + orbit; the image is made from the scenes of that orbit only, never a patchwork of two orbits. Order: September ≤ 5 % cloud with the least snow, then August, then July, then least cloudy ≤ 30 % ("some clouds").
- **Images:** Process API, Sentinel-2 **L1C** of the chosen day, Copernicus Browser true-colour process (maxR 3, midR 0.13, sat 1.3, gamma 2.3, gOff 0.01, Rayleigh 0.013 / 0.024 / 0.041). Band combinations: Natural B04-B03-B02, False 1 (infrared) B08-B04-B03, False 2 B8A-B11-B12 (internal keys `natural`, `false1`, `false2`; saved settings from the old names `false` and `parece` are converted).
- **Parked experiment:** ice edge lines (ablation zone, from a spectral index) were taken out because debris-covered tongues are not detected. Code, method and results are kept locally in `experiments/ice-edge/` (see its README; not in the repository). The Worker still passes the requested image format (JPEG or PNG) to Copernicus.
- **Strip pictures for the 3D view:** the 3D view needs only the strip (4 km wide, a few km up the glacier), a small part of the glacier area, so it asks the relay for a picture of just the box around the strip (`stripImageSpec`, `loadImage(g, yr, spec)`), at the same native 10 m ground pixels (Natural and False 1; the 20 m bands of False 2 are upsampled by Copernicus, bilinear). The box is cut in whole 10 m steps from the geometry in the baked terrain file, so every visitor asks for the same picture and the relay's KV cache serves it; the Worker needs no change (it checks only area, date and size). The whole-area picture is reused when the map has already loaded it and has the full 10 m (`imageHere`); if strip pictures cannot be had, the whole one is used and no more strips are tried in that visit (`stripPicturesOff`). While the 3D view is open the map's own pictures wait (`deferredLoads`), so a 3D visitor does not also download the whole-area pictures of the map. `tools/warm-up.html` fills the cache with both kinds. Every whole-area picture is 10.0 m per pixel at the moment (none hits the 2,500 px limit); keep it so when changing margins.
- **Latest image (chip "Latest" in the One year row):** the newest scene of the last 60 days with at most 30 % cloud, cloud shadow and cirrus over the 1850 outline and at most 1 % over the tongue circle (`findLatest`, two statistics requests per glacier and day, kept 1 day by the Worker). The scene temporarily replaces the scene of its year in `state.available` (`state.latest` remembers the original; `restoreLatest()`), so downloads, glacier facts and credits work as for a year. It ends when a year is picked, the mode leaves One year, or the glacier changes. The Worker accepts the rolling window (at most 75 days) and a picture of any day in the last 130 days.
- **Caches:** browser IndexedDB `tfs-cache`; Worker KV `CACHE` (180 days; the current summer's scene scores 1 day; identical simultaneous requests share one fetch). The free plan allows 1,000 KV writes a day; a full warm-up is about 300.
- **Other sources, without the relay:**
  - EOX Sentinel-2 cloudless tiles (background);
  - OpenStreetMap;
  - swisstopo: identify for the per-glacier volume (the ice thickness map layer was removed, see `experiments/ice-thickness-layer/`).
  - swisstopo colour topographic map (Pixelkarte farbe, WMTS), an optional base map; free to use with the source reference "© swisstopo". The swissALTI3D hillshade (WMTS) is a second optional base map, same terms.

## Rules

- **Gallery uploads (`worker/worker.js`, "gallery" section):** the only place visitors write data. Keep every check (Turnstile, size, real file type and pixel size, fixed metadata list, queue cap, pending never served). Needs R2 `GALLERY`, `TURNSTILE_SECRET`, `TURNSTILE_SITEKEY`, `GALLERY_ADMIN_TOKEN` (see README, "Gallery"). `serve.py` has no gallery.

- **Raise `CDSE.version`** (section 3) whenever scene scoring or image rendering changes; otherwise browsers keep old images.
- **After any change to `worker/worker.js`,** tell the user to paste it into the Cloudflare dashboard (Worker → Edit code → Deploy). GitHub does not deploy the Worker. New request types must also be allowed in the Worker's `checkProcess` / `checkStatistics`.
- **`GLACIER_INFO` and all figures:** only documented facts, with a source. Unknown name origins say so. Never invent data, field names or sources.
- **Licences:**
  - GLAMOS length change, volume change and Swiss-wide volume: non-commercial (the file headers say so, although the landing pages say CC BY 4.0);
  - EOX background: CC BY-NC-SA 4.0;
  - Copernicus data, GLAMOS inventories and radar ice thickness (CC BY 4.0): allow commercial use.
  
  So the site is non-commercial. Keep the credits line and the Sources list complete when adding data.
  - Project licences: code MIT (`LICENSE`), own texts CC BY 4.0; third-party data and the font keep theirs (see README, "Licences").
- **The user edits files himself between sessions.** Always work from the current file, never from an older copy.
- **No CSS or SVG filters on page elements for image effects:** Safari on iPhone ignores them. Process pixels in a canvas.
- **Edit whole CSS rules or functions;** partial find/replace has broken selectors before. Check the result.
- **Async searches (`checkYears`) use a generation counter;** keep stale results from overwriting newer ones.

## Style

- **Calm and compact.** Little text; explanations go into the collapsed "About Tongues from Space" or behind small "i" buttons. Small notes 11–11.5 px.
- **Red accent `--accent: #C8322A`** for headers and loss; **blue `--crevasse`** for ice and water. Stats in white cards: red uppercase card header with an icon, grey tiles.
- **Left panel:** numbered steps 1 Choose a glacier, 2 Compare, 3 Create and share. On phones: map first, then that panel, then the story; two fingers move the map.
- **UI text in English.**

## Testing a change

1. **Automatic:** `python3 scripts/check_syntax.py` (and `check_types.py` where Node exists), then `python3 -m unittest discover -s tests -v` (needs `pip install -r tests/requirements.txt` and `python3 -m playwright install chromium`). The workflows run the same before every deploy. Add a test when a bug was found by hand; the page's functions can be called in `page.evaluate`.
2. **Locally with real data:** `python3 scripts/serve.py`, then open http://localhost:8000. Check the status box under the years ("Scenes found…"), compare and timelapse, the three colour modes, the tabs, and a phone-size window (two-finger map, layout).
3. **Animation:** create a short 9:16 video; it should play in QuickTime and upload to Instagram or TikTok. `ffprobe` should show H.264, 1080×1920, 30 fps.
4. **Worker changes:** test locally with `serve.py` first (same request shapes), then deploy to Cloudflare and open `<worker-url>/cdse/ping` → `{"relay":true,"managed":true}`.
5. **Build script:** `python3 scripts/build_outlines.py` should print the ten glaciers with areas and length changes.

## Deployment checklist for the user

- **Worker:** paste `worker/worker.js` into Cloudflare → Deploy.
- **Repository variable `CDSE_RELAY_URL`** = Worker address; changing it requires a new workflow run.
