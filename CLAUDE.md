# CLAUDE.md: Swiss Glacier Tongues from Space

Public dashboard of the tongues of the ten largest Swiss glaciers (and, as a second region, the Vatnajökull ice cap in Iceland) in Sentinel-2 imagery, one clear late-summer scene per year since 2016, with GLAMOS statistics, a single-image export and an animation (video) export. Site: https://tonguesfromspace.org/. Non-commercial (see Licences).

## Rules (non-negotiable)

- External numbers (GLAMOS, Wikipedia, papers, press) appear EXACTLY as the source states them: no rounding, unit conversion, midpoints or respelling. If you cannot read the source, leave the figure out. Computed values are labelled as computed.
- Site is non-commercial (GLAMOS length/volume data and EOX background are non-commercial). Keep credits and the Sources list complete.
- No CSS/SVG filters for image effects (Safari on iPhone ignores them); process pixels in a canvas.
- Raise the image-cache version (`CDSE.version`, `js/03-imagery.js`) whenever scene scoring or rendering changes. (The relay by meaning under `/api/` needs no bump: its cache keys contain a hash of the evalscripts.)
- Glaciological years are named after the year they end in (2017 = Oct 2016 to Sep 2017).
- UI text in English. Calm, compact style; red accent #C8322A for loss, blue for ice and water; Schibsted Grotesk.

The long forms of these rules (external numbers, licences, glaciological years, style) are in "Rules" and "Style" below; this block is the short list.

## Where things are

The full file table, the section-by-section map of `js/` and the data flow are in **docs/REFERENCE.md** (read the row of the file you are about to change). Setup and operations: **docs/SETUP.md**. Data sources and licences: **docs/SOURCES.md**. The rewrite plan and its state: **REWRITE.md**.

Short version:

- **Pages:** `index.html` (the dashboard), `home.html`, `gallery.html`, `size.html`; colours and typeface are only in `css/tokens.css` (the style sync to the sister sites is retired).
- **Code:** `js/main.js` imports the sections `js/01-…14-*.js` in order; they are ES modules, bundled by esbuild in `scripts/build_site.py`. `js/regions.js` (the region records, data only) and `js/00-regions.js` (picks the region, writes the data tags) are the two classic scripts.
- **Wiring rules (keep them when you edit):** import from files with a lower number; for something in a higher-numbered file use `wire.name` (`js/wire.js`; the owner registers it at its top); to assign a variable that lives in another file use its `setX()`; differences between regions are `features` flags in `00-regions.js`, never `REGION.id === ...`; new helpers go in the lowest file that needs them.
- **Records are the source of truth** for what a glacier is, where its box, strip and camera are, and which scenes are pinned: `data/regions/` (walkthrough, `npm run walkthrough:serve`; docs/WALKTHROUGH.md). `data/boxes.js`, `data/scenes.json` and `worker/glacier-index.json` are generated from them: never edit these by hand; `npm run check` fails if they differ.
- **Data** in `data/` (generated or hand-made), **tooling** in `scripts/`, the Worker in `worker/`, tests in `tests/`.
- **Checks:** `npm ci`, then `npm run check` (syntax + types) and `npm test`.

## Rules

- **Gallery uploads (`worker/worker.js`, "gallery" section):** the only place visitors write data. Keep every check (Turnstile, size, real file type and pixel size, fixed metadata list, queue cap, pending never served). Needs R2 `GALLERY`, `TURNSTILE_SECRET`, `TURNSTILE_SITEKEY`, `GALLERY_ADMIN_TOKEN` (see README, "Gallery"). `serve.py` has no gallery.

- **EXTERNAL NUMBERS ARE COPIED, NEVER CREATED (strong rule, no exceptions).** Every number, date, name or quantity that comes from an external source (GLAMOS, Wikipedia, papers, press, SVGW, swisstopo, Met Office, NVE, NPI, …) must appear on the site **exactly as the source states it**: same value, same precision, same unit. Claude must NOT round, convert units, average a range into a midpoint, spell a number as digits or the reverse ("ten kilometre" → "10 km"), merge two figures, compute a derived value and present it as the source's, or "tidy" a figure from memory. If the source says "900-950 million m³", the page says that, not 0.93 km³. If the source gives a range or "about", keep it. A value Claude calculates itself (sums, rates, unit conversions) is shown as computed here, labelled as such, and never attributed to the source. When Claude cannot open the source and read the figure, it does not write the figure: it leaves it out or asks the user. Quote the source's wording for the figure in the code comment or in `gfn`, so it can be checked. Before saying a text is done, check each external figure against the source page (for Wikipedia: `python3 scripts/check_external_numbers.py`). A number that fails is fixed or removed, never kept because it "looks right".
- **Raise `CDSE.version`** (section 3) whenever scene scoring or image rendering changes; otherwise browsers keep old images.
- **After any change to `worker/worker.js`,** it deploys with the next push to main (`deploy.yml` runs `wrangler deploy`; secrets and dashboard variables are kept, `keep_vars`); nothing is pasted into the dashboard any more. New request types must also be allowed in the Worker's `checkProcess` / `checkStatistics`.
- **`GLACIER_INFO` and all figures:** only documented facts, with a source. Unknown name origins say so. Never invent data, field names or sources.
- **Licences:**
  - GLAMOS length change, volume change and Swiss-wide volume: non-commercial (the file headers say so, although the landing pages say CC BY 4.0);
  - EOX background: CC BY-NC-SA 4.0;
  - Copernicus data, GLAMOS inventories and radar ice thickness (CC BY 4.0): allow commercial use.
  
  So the site is non-commercial. Keep the credits line and the Sources list complete when adding data.
  - Project licences: code MIT (`LICENSE`), own texts CC BY 4.0; third-party data and the font keep theirs (see README, "Licences").
- **The user edits files himself between sessions.** Always work from the current file, never from an older copy.
- **No CSS or SVG filters on page elements for image effects:** Safari on iPhone ignores them. Process pixels in a canvas.
- **Edit whole CSS rules or functions;** partial find/replace has broken selectors before. Check the result.
- **Glaciological years:** a yearly value (mass balance, length change, national loss) is named after the year in which it ends in September: 2017 = October 2016 to September 2017, which is what the summer picture of 2017 shows. Selected years count with both ends: a sum over 2017–2019 adds the values of 2017, 2018 and 2019 (`r_in`, `selRows`, `inRange`), the ice at the start of it is `iceVolume(lo - 1)`. Charts show every year and highlight the selected ones.
- **Async searches (`checkYears`) use a generation counter;** keep stale results from overwriting newer ones.
- **When the owner asks in chat to onboard a glacier or a group of glaciers (or a region), do this at once, without asking first:** (1) if a place or coordinates are unclear, find them (web search); (2) **look on the web for the best outline sources for that place**: a national or regional inventory is better than the global RGI 6.0 (about 2000) that `npm run onboard` fetches itself; read each source's own page (never state a licence, date or number from memory; the rule on external numbers applies), compare with `walkthrough/outline-sources.json`, add a verified national source to that file, and put what you found into the proposals with `npm run walkthrough -- add-source <region> <id> "<name>" <url>` (its licence is then "NOT READ" for the owner); use a source's own fetcher when one exists (`propose-glamos` for Swiss glaciers); (3) run `npm run onboard -- <region-id> "<name>@lat,lon" ... [--region-name "Name"]`: it creates the records, writes every proposal that can be written (record, outlines incl. the oldest dated one, picture box, tip as a first guess, season copied from the closest region and said so, map layers), starts the walkthrough server and **opens it in a new browser window** on the first step that needs a person; (4) tell the owner in a few lines what was filled, what could not be and why (the command prints it), which better source you found or did not find, and the link. Fill in everything that can be filled in; **never confirm anything, and never write a confirmation or a licence for the owner**: confirming is theirs (the wizard, with a reason). Details: docs/WALKTHROUGH.md, "Starting from a chat request".
- **Minimum size for onboarding: 10 km².** A glacier known to be smaller (inventory area) is not onboarded (`MIN_ONBOARD_KM2` in `shared/geo.ts`; `onboard`, `onboard-paul`, `propose-glamos` skip it and say so). Do not work around it when a chat request names one; tell the owner it was left out. **What counts as a glacier (owner's decision 2026-10-26, the same in every region):** every inventory unit of 10 km² and over, outlets of an ice cap included as glaciers of their own, and **at most 26 per region** (the largest by inventory area; `MAX_PER_REGION` in `shared/geo.ts`; `onboard`, `onboard-paul` and `propose-glamos` apply it and say what was left out). The older "ten largest per region" texts (`js/regions.js`, `build_regions.py`, `import-site.ts`, the README) describe what is published today and are rewritten when the glaciers of the new rule are onboarded and confirmed; do not claim more glaciers on the site than exist.
- **New glaciers, caps or outlets: placement comes first.** When the user proposes adding any (Swiss glacier, ice cap, region outlet), the first step, before data builds, texts, scenes, terrain, Landsat, imagery or anything else, is to go over the placement of the image box (`lat`, `lon`, `half`, `bounds`), the 3D view (start camera `cam`) and the 3D strip (`strip3d`: tip, azimuth, half width, back, up) together with the user, using `scripts/tools/box-editor.html` and `scripts/tools/view3d-editor.html`. Propose a placement from the rule (`icecap_lib.derive_view`), show it, and wait for the user's confirmation or corrections; only then build the rest. Everything downstream (cloud masks, Worker centres, terrain bundle, strip pictures, caches) depends on these numbers, so changing them later means redoing it all.

## Review walk-through (local)

`python3 scripts/serve.py`, then http://localhost:8000/scripts/tools/review.html: one glacier at a time, five steps (Box and outline, Pictures by year, 3D view, Numbers and texts, Photos/trails/Street View). Each step shows the real site or an editor in a frame, what to look for, the machine checks of that step with their fix commands, and **Looks good (G)** / **Flag (F, with a note)**; N jumps to the next step that needs a look. `scripts/review_lib.py` (steps, fingerprints, the `/review/state` and `/review/sign` endpoints in `serve.py`) keeps the sign-offs in `data/review-signoffs.json` (committed): each stores a fingerprint of the data its step looks at, so it turns **stale** by itself when that data changes (box/tip/strip, scenes/Landsat/oldest, terrain/camera, texts/numbers, photos/Street View/trails). **Placement blocks the rest:** while step 1 (box, outline, strip) is flagged or has an open note, steps 2 to 5 are locked (🔒, `Looks good` refused by the server); a sign-off on steps 2 to 5 stores the box fingerprint it was made on (`dep`), so a later box change turns them stale. In step 1 the button "Use the box editor's result as the note" copies the editor's line into the note. When applying a box change, rebuild what depends on it (terrain, cloud masks, Worker centres, imagery), write a `reply`, and the owner signs step 1 off again. Machine checks come from `scripts/.board-cache/docs` (run `board_sync.py` first). **At the start of glacier work read `data/review-signoffs.json`: every record with a `note` and no `reply` is a task from the owner, whether its state is `flag` or `ok` (an `ok` with a note = approved apart from that request); do it, write a `reply` into the record (what was done), and tell the owner; after a flag they sign the step off again. Never write an `ok` sign-off.** Not yet: the add-a-glacier wizard (the same screens with locked order), import of the board's old `boxDone`/`viewDone` ticks.

## Glacier checklist board

`docs/ADD_A_GLACIER.md` is the standard for every glacier/outlet (all pieces required, tiling over 24.9 km, excuses in `data/audit-exceptions.json`). The **board** is an artifact (URL in the doc, memory `project-glacier-board`) whose page `scripts/board_app.html` is static and reads everything from the artifact database; the page is republished only when its code changes, **data changes never need a republish**:

| Collection | Written by | Content |
|---|---|---|
| `meta/schema` | `scripts/audit_glaciers.py` (`SCHEMA`: key, label, stage, required, fix command), via sync | the one list of checks the page, docs and audit share, plus `syncedAt` |
| `glaciers/<id>` (outlets `<id>~<n>`) | audit, via sync | per check `{state ok/missing/warn/excused/info/na, text, sub, detail}`, the Sentinel-2 / terrain / yearly years, `syncedAt` |
| `notes/<id>` | the owner | `text`, `reviewed`, `boxDone`, `viewDone` (sign-offs are the owner's, never set by Claude) |
| `tasks/<taskId>` | owner creates, Claude answers | `{glacier, text, status open/doing/done/wontdo, reply, createdAt, doneAt}` |
| `thumbs/<id>--l0..`, `--s2` | `scripts/board_thumbs.py` | `{glacier, kind landsat/s2, items[{year, date, img}]}`, at most 200 KB per document (Aletsch's older per-year documents stay as they are) |

**Refresh (Claude, after any change to glacier data, builds, regions or the checklist, and before saying a glacier is done):** `python3 scripts/board_sync.py` (add `--scan` to re-run the page-driven scans: `board_scan.py` = Sentinel-2 years the site finds + oldest aerial, spends Copernicus requests for glaciers nobody opened before; `board_extras.py` = newest scene), then push `scripts/.board-cache/push-plan.json` with ArtifactData `batch` (one call per batch; a write to an existing document needs `if_version`: use the version of the last push (another chat may have pushed since: `list` the collection with `out_dir` to read the current versions), and on `version_mismatch` the error names the current one, resend with it; never touch `notes`, `tasks`). After the push, `list` the `glaciers` collection and `delete` every id that is no longer in `push-plan.json` (a removed glacier would otherwise stay on the board). The artifact URL is in `docs/ADD_A_GLACIER.md`; the ArtifactData tool is deferred, load it with ToolSearch first. **Adding or changing a glacier or outlet counts as a change that triggers this:** the board picks up new outlets by itself from the region data files; a new Swiss glacier needs its site id in `SITE_ID` (`audit_glaciers.py` warns), and the Sentinel-2 years and oldest aerial of a new glacier stay `n/a` until `board_scan.py --only <id>` has run. **Tasks:** at the start of any glacier work (and whenever the user says so) `list` the `tasks` collection and handle every task with status `open`: set `doing` (update with `if_version`), do the work, then `update` with `status: done` (or `wontdo` with the reason), `reply` (what was done, the files changed, what is left) and `doneAt`. Read `notes` for context. Two local editors produce a one-line request that the owner pastes into a task: `scripts/tools/box-editor.html` (picture box and 3D strip, with the oldest and newest outline) and `scripts/tools/view3d-editor.html` (the real 3D view in an iframe: orbit/zoom or sliders; the start camera `cam {az, el, dist}` in radians/radians/metres, read from `v3d.getCam()`). A hand-set start camera goes in `V3D_VIEW[id].cam` (Swiss) or `strip3d.cam` of the region data (read by `stripFor`/`stripOf`, applied in `open3D`); sign-offs `notes.boxDone` and `notes.viewDone` are the owner's. **Thumbnails:** `python3 scripts/board_thumbs.py --landsat-only` (free, local files), `--s2-limit N` (Sentinel-2 drawn by the real page through the relay: uncached images cost Copernicus requests and KV writes, so spread big jobs over days, about 250 images a day at most, the public site shares that quota), then `--plan` prints the push batches (<= 950 KB) and `--mark-pushed 0 1 ...` records them; state in `scripts/.board-cache/thumbs-state.json`. **Ids:** the site's `#g=` id for a Swiss glacier is a short name (`aletsch`, `trift`, `zmutt`…) or `sgi-<inventory id>` (`SITE_ID` in `audit_glaciers.py`, doc field `siteId`), not the inventory id the board uses as its key; an unknown id silently opens Aletsch, so `board_scan.py` fails a glacier whose page does not open the intended one. **Enforcement:** a Stop hook (`.claude/settings.json` -> `scripts/board_reminder.py`) blocks the end of a turn once when the data the board is built from changed since the last sync (content hash of the region data files, terrain manifest, trails/Landsat/oldest file lists, texts, exceptions…; stamp in `scripts/.board-cache/last-sync.json`); after pushing, read `meta/schema` back from the board (ArtifactData `get` with `out_dir`) and run `python3 scripts/board_sync.py --stamp <that file>`: the stamp is refused unless the board's `syncedAt` equals the one just pushed, so it cannot be set before the push. `tests/test_board.py` (part of the normal test run) checks the board's data and that every Swiss board link opens the intended glacier. Facts are snapshots: the page shows their age and warns after 3 days, so refresh before reporting status.

## Style

- **Calm and compact.** Little text; explanations go into the collapsed "About Tongues from Space" or behind small "i" buttons. Small notes 11–11.5 px.
- **Red accent `--accent: #C8322A`** for headers and loss; **blue `--crevasse`** for ice and water; **typeface Schibsted Grotesk** (`css/tokens.css`). Stats in white cards: red uppercase card header with an icon, grey tiles.
- **Left panel:** numbered steps 1 Choose a glacier, 2 Compare, 3 Create and share. On phones: map first, then that panel, then the story; two fingers move the map.
- **UI text in English.**

## Testing a change

1. **Automatic:** `python3 scripts/check_syntax.py` (and `check_types.py` where Node exists), then `python3 -m unittest discover -s tests -v` (needs `pip install -r tests/requirements.txt` and `python3 -m playwright install chromium`). The workflows run the same before every deploy. Add a test when a bug was found by hand; the page's functions can be called in `page.evaluate`.
2. **Locally with real data:** `python3 scripts/serve.py`, then open http://localhost:8000. Check the status box under the years ("Scenes found…"), compare and timelapse, the three colour modes, the tabs, and a phone-size window (two-finger map, layout).
3. **Animation:** create a short 9:16 video; it should play in QuickTime and upload to Instagram or TikTok. `ffprobe` should show H.264, 1080×1920, 30 fps.
4. **Worker changes:** test locally with `serve.py` first (same request shapes), then deploy to Cloudflare and open `<worker-url>/cdse/ping` → `{"relay":true,"managed":true}`.
5. **Build script:** `python3 scripts/build_outlines.py` should print the ten glaciers with areas and length changes.

## Deployment checklist for the user

- **Site:** commit and push; the GitHub Action builds and deploys in a few minutes (Actions tab, green tick).
- **Worker:** deployed by the same workflow (needs the secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and the variables `CF_KV_CACHE_ID`, `CF_R2_GALLERY_BUCKET`, `CF_R2_LANDSAT_BUCKET`).
- **Repository variable `CDSE_RELAY_URL`** = the site's own address `https://tonguesfromspace.org/` (the Worker serves site and relay); changing it requires a new workflow run.
