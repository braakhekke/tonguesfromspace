# CLAUDE.md: Swiss Glacier Tongues from Space

Public dashboard of the tongues of the ten largest Swiss glaciers in Sentinel-2 imagery, one clear late-summer scene per year since 2016, with GLAMOS statistics, a single-image export and an animation (video) export. Site: https://braakhekke.github.io/tonguesfromspace/. Non-commercial (see Licences).

## Files

| File | Role |
|---|---|
| `index.html` | The whole site: one file, no build step. Leaflet 1.9.4 from cdnjs. |
| `glaciers.js` | Generated by `scripts/build_outlines.py` (GitHub Action). Never edit by hand. |
| `fonts/` | Schibsted Grotesk as one variable woff2 (made from the TTF in `fonts/Schibsted_Grotesk/`), loaded by `@font-face` in `index.html`; no Google Fonts. The deploy copies only the `.woff2` and `OFL.txt`. |
| `config.js` | Written by the deploy workflow: `window.TFS_CONFIG = { relay: <CDSE_RELAY_URL> }`. Not in the repo. |
| `scripts/build_outlines.py` | Downloads GLAMOS inventories (SGI1850, SGI1973, SGI2023) and length-change CSV (every survey is kept as `series`); finds the tongue tip of each glacier (lowest outline point, swisstopo height service, about 2 minutes); adds inventory statistics; writes `glaciers.js`; leaves it untouched if the data did not change. Standard library only. |
| `scripts/serve.py` | Local server + Copernicus relay. Credentials: env `CDSE_CLIENT_ID` / `CDSE_CLIENT_SECRET`, or `scripts/.cdse-credentials` (gitignored), or a prompt. |
| `worker/worker.js` | Cloudflare Worker = public Copernicus relay with request validation and KV cache. |
| `.github/workflows/deploy.yml` | On push to main, monthly cron, or manual: build data → commit `glaciers.js` → write `config.js` → deploy Pages. |

## Where things live in `index.html`

Script sections are marked with `/* ===== n. Title ===== */` comments:

1. **Static data:** `ICE_2024`, `VOLUME_LOSS` (national yearly loss %), water constants, `DEFAULTS` (built-in top ten: tongue position `tongue`, zoom `tz`, texts), `GLACIER_INFO` (fun fact, name origin, source).
2. **Glacier list:** built-in list, or the SGI2023 ranking from `glaciers.js`; `shortName()` naming rule (local name without the word for glacier).
3. **Imagery:** `CDSE` settings and `version`, `LAST_DAY`, scene scoring (`SCENE_EVALSCRIPT`, `pickScene`, `findScene`), colour process (`TRUE_COLOR`, `STYLE_BANDS`, `evalscriptFor`), relay calls (`cdse()`), caches, `loadImage`.
4. **State and URL hash.**
5. **Map:** panes, OSM, EOX background (`BG_YEAR`), swipe, timelapse, outlines, measuring, brightness (canvas, `adjustedUrl`).
6. **Scene search** for the selected glacier (`checkYears`, `statusLine`).
7. **Rendering:** left panel, `renderStory` (tabs What to see / Stats / Switzerland, collapsed About), stats cards, glacier volume (`glacierVolume`), water section, `cumulativeChart`.
8. **Controls:** glacier boxes overview, tongue indication, layer panel (grouped: This glacier, Overview, Background).
10. **Phones:** glacier dropdown, map tools, two-finger map, sharing.
11. **Create animation:** framing, drawing, WebCodecs H.264 encoding, `muxMp4` (own MP4 packer).
9. **Boot** (last in the file).

## Data flow

```
browser ── /cdse/statistics, /cdse/process ──> relay ──> Copernicus Data Space (Sentinel Hub APIs)
           relay = worker/worker.js on the public site (config.js), scripts/serve.py locally
```

- **Scene choice:** Statistical API, Sentinel-2 L2A, SCL classes (cloud 3, 8, 9, 10; snow 11), 1 July to 20 September (`LAST_DAY`; 2024 until 14 September). Order: September ≤ 5 % cloud with the least snow, then August, then July, then least cloudy ≤ 30 % ("some clouds").
- **Images:** Process API, Sentinel-2 **L1C** of the chosen day, Copernicus Browser true-colour process (maxR 3, midR 0.13, sat 1.3, gamma 2.3, gOff 0.01, Rayleigh 0.013 / 0.024 / 0.041). Band combinations: Natural B04-B03-B02, Infrared B08-B04-B03, Parece B8A-B11-B12.
- **Parked experiment:** ice edge lines (ablation zone, from a spectral index) were taken out because debris-covered tongues are not detected. Code, method and results are kept in `experiments/ice-edge/` (see its README). The Worker still passes the requested image format (JPEG or PNG) to Copernicus.
- **Caches:** browser IndexedDB `tfs-cache`; Worker KV `CACHE` (180 days; the current summer's scene scores 1 day; identical simultaneous requests share one fetch). The free plan allows 1,000 KV writes a day; a full warm-up is about 300.
- **Other sources, without the relay:**
  - EOX Sentinel-2 cloudless tiles (background);
  - OpenStreetMap;
  - swisstopo: identify for the per-glacier volume (the ice thickness map layer was removed, see `experiments/ice-thickness-layer/`).

## Rules

- **Raise `CDSE.version`** (section 3) whenever scene scoring or image rendering changes; otherwise browsers keep old images.
- **After any change to `worker/worker.js`,** tell the user to paste it into the Cloudflare dashboard (Worker → Edit code → Deploy). GitHub does not deploy the Worker. New request types must also be allowed in the Worker's `checkProcess` / `checkStatistics`.
- **`GLACIER_INFO` and all figures:** only documented facts, with a source. Unknown name origins say so. Never invent data, field names or sources.
- **Licences:**
  - GLAMOS length change: non-commercial;
  - EOX background: CC BY-NC-SA 4.0;
  - Copernicus data and GLAMOS inventories (CC BY 4.0): allow commercial use.
  
  So the site is non-commercial. Keep the credits line and the Sources list complete when adding data.
- **The user edits files himself between sessions.** Always work from the current file, never from an older copy.
- **No CSS or SVG filters on page elements for image effects:** Safari on iPhone ignores them. Process pixels in a canvas.
- **Edit whole CSS rules or functions;** partial find/replace has broken selectors before. Check the result.
- **Async searches (`checkYears`) use a generation counter;** keep stale results from overwriting newer ones.

## Style

- **Calm and compact.** Little text; explanations go into the collapsed "About the images, data and sources" or behind small "i" buttons. Small notes 11–11.5 px.
- **Red accent `--accent: #C8322A`** for headers and loss; **blue `--crevasse`** for ice and water. Stats in white cards: red uppercase card header with an icon, grey tiles.
- **Left panel:** numbered steps 1 Glacier, 2 Visualisation, 3 Download and share. On phones: map first, then that panel, then the story; two fingers move the map.
- **UI text in English.**

## Testing a change

1. **Syntax:** extract the last `<script>` block and run `node --check` on it.
2. **Locally with real data:** `python3 scripts/serve.py`, then open http://localhost:8000. Check the status box under the years ("Scenes found…"), compare and timelapse, the three colour modes, the tabs, and a phone-size window (two-finger map, layout).
3. **Animation:** create a short 9:16 video; it should play in QuickTime and upload to Instagram or TikTok. `ffprobe` should show H.264, 1080×1920, 30 fps.
4. **Worker changes:** test locally with `serve.py` first (same request shapes), then deploy to Cloudflare and open `<worker-url>/cdse/ping` → `{"relay":true,"managed":true}`.
5. **Build script:** `python3 scripts/build_outlines.py` should print the ten glaciers with areas and length changes.

## Deployment checklist for the user

- **Site:** commit and push; the GitHub Action builds and deploys in a few minutes (Actions tab, green tick).
- **Worker:** paste `worker/worker.js` into Cloudflare → Deploy.
- **Repository variable `CDSE_RELAY_URL`** = Worker address; changing it requires a new workflow run.
